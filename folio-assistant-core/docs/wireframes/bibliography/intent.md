# bibliography/ page: as-is intent

**Covers:** the `bibliography` visualiser `folio-assistant-core` declares in `folio-assistant-core.json` (`renderedBy: bibliography-page`, `coversKinds: [references, catalogue]`, `subgraphs: directory`), routed at `en/folio-assistant-core/bibliography/`. It is generated by `folio-assistant-core/scripts/bibliography-page.ts` (`bun run cat bibliography:page`, the `bibliography-page` Tool) and gated by `check:bibliography`.

**Candidate:** `as-is.html`, the index page, with the page of one sub-graph drawn below it. Checked at web 1280 and mobile 390.

**Who it is for:** a reader or an author of a folio who wants a reference the knowledge graph holds, whether a folio cites it (a `references` node) or a catalogue holds it (a Dublin Core record). It works like the glossary viewer, limited by path to sub-graphs and single assets.

**What they need to do:** find a reference, read its citation, see where it came from and whether the library holds it, and export the whole list, one sub-graph's list, or one reference, in the format their tool reads.

**What it must show**, as the generator writes it:

On the index (`<route>/`):
- what the page holds: `references` directories' `folio-reference/v1` nodes and `catalogue` directories' Dublin Core records, as one list;
- the export of every reference shown: BibTeX, CSL-JSON, RIS and Dublin Core / BIBO JSON-LD, as files beside the page;
- a "By sub-graph" line linking each declared directory's page, with its count;
- a filter box with a live count;
- every page of the route keeps out of the site's search index (`search_exclude: true`), so the site's search data does not carry the bibliography;
- a list longer than 500 references is not written out: the page says how many it holds, links the sub-graphs (on the index) or the documents (on a sub-graph's page) whose pages list them, lists only the few no page below lists, and keeps its exports; in place of the list it offers a search box over the route's static, sharded search index (`<route>/search/`, `bibliography-search.ts`): every word of the query must begin a word of the reference, results show their count by sub-graph and by decade (each a filter) and link the page that lists each reference;
- per reference, in an ordered list: the citation (up to three authors then "et al.", year, title, container, volume, issue, pages, publisher); its key as a link to its own page (`<route>/<sub-graph>/<key>/`, a slash address with no `#`), which a click opens in the right-side panel; its provenance (`catalogue` or `authored`); its DOI or URL; its ISBN; the source file it was read from; where the library holds it; and its own export as BibTeX, RIS and CSL-JSON downloads. A reference EXTRACTED from a document's reference list (`provenance: extracted`) has no page of its own: its key opens its detail in the side panel from the page that lists it, and its export is in that detail.

On each reference's own page (`<route>/<sub-graph>/<key>/`; for a library item, its asset page): every bibliographic field, every place the work can be read (its URL, DOI, arXiv page, repository and pinned copy, DSpace handles), where it sits in the KG, and its export. An entry with no title shows its citation as the source printed it.

On each sub-graph's page (`<route>/<sub-graph>/`): the directory, its layer and kind, a link back to all references, the same four exports over that directory alone, and the filter and list.
